First triangle

Instance, surface, adapter, device, swapchain, pipeline, draw. The same chain you build in Vulkan, with the synchronization, memory and layout work moved into the implementation.

You write src/common/gpu.c and the TODOs in src/step1_triangle/main.c. Window, input and build are done. Each section gives the goal, the Vulkan analog, the API to look up, the traps, and a checkpoint. Solutions are folded: open one only after a real attempt.

§0Setup and mental model

One-time setup, from the repository root:

pwsh -File setup.ps1

It fetches the pinned Dawn release (Chrome's WebGPU implementation: static lib, headers, tint.exe), Freedoom for later, and copies the runtime DLLs Dawn loads at startup into third_party/dawn/runtime. Then open doomgeneric-wgpu.sln, keep step1_triangle as startup project, press F5. The console says Gpu_Init: not implemented yet. You start from there.

Vulkan to WebGPU

VulkanWebGPU C APIWhat changes
VkInstanceWGPUInstanceNo layers, no extension list.
VkPhysicalDeviceWGPUAdapterRequested asynchronously with preferences; not enumerated and scored.
VkDevice + VkQueueWGPUDevice + WGPUQueueOne queue for everything. No families.
VkSurfaceKHR + VkSwapchainKHRWGPUSurface + wgpuSurfaceConfigureThe swapchain is surface state. Reconfigure on resize; no oldSwapchain.
vkAcquireNextImageKHR / vkQueuePresentKHRwgpuSurfaceGetCurrentTexture / wgpuSurfacePresentNo semaphores, no fences.
VkCommandPool + VkCommandBufferWGPUCommandEncoder → WGPUCommandBufferOne-shot. No reset, no reuse, no secondary buffers (render bundles are the closest).
vkCmdBeginRenderingwgpuCommandEncoderBeginRenderPassLoad/store ops per attachment. No image layouts.
VkPipeline + VkPipelineLayoutWGPURenderPipelinelayout = NULL derives the layout from the shader. Viewport, scissor, blend constant stay dynamic.
VkShaderModule (SPIR-V)WGPUShaderModule (WGSL text)Dawn's Tint compiles WGSL to HLSL/DXIL or SPIR-V.
Descriptor setsBind groupsStep 2.
Barriers, layouts, semaphores, fencesNoneDawn tracks usage per pass and inserts them.
sType / pNextWGPUChainedStruct.sType / nextInChainSame idea, fewer chains.
VkResultError callbacksFailed calls still return an object, marked invalid. Using it is another error.
vkDestroy*wgpu*ReleaseReference counted. Release while the GPU still uses it is fine.

Four C API conventions

  1. Start every struct from its _INIT macro: WGPUFoo foo = WGPU_FOO_INIT;. It sets sType on chained structs and the non-zero defaults (multisample.mask = 0xFFFFFFFF, depthSlice = WGPU_DEPTH_SLICE_UNDEFINED). {0} is the WebGPU version of a missing sType.
  2. Strings are WGPUStringView { data, length }. length = WGPU_STRLEN means null-terminated; Gpu_Str() in gpu.h builds one. Strings you receive are not null-terminated: print them with "%.*s", SV(view) (macro at the top of gpu.c).
  3. Async calls return a WGPUFuture and take a *CallbackInfo with a mode: WaitAnyOnly fires only inside wgpuInstanceWaitAny; AllowProcessEvents also inside wgpuInstanceProcessEvents; AllowSpontaneous anywhere, any thread.
  4. Getters that return owned memory fill a struct you later pass to wgpu*FreeMembers.

§3Adapter

Get a GPU that can present to the surface, on the backend passed to Gpu_Init.

  • VulkanvkEnumeratePhysicalDevices + scoring
  • LearnWebGPUThe adapter
  • WGPURequestAdapterOptions
  • WGPURequestAdapterCallbackInfo
  • wgpuInstanceRequestAdapter
  • WGPUFutureWaitInfo
  • wgpuInstanceWaitAny
  • wgpuAdapterGetInfo
  • wgpuAdapterInfoFreeMembers

You describe what you want (power preference, compatible surface, backend) and Dawn picks. The request is asynchronous: pass a callback with mode WaitAnyOnly, put the returned future in a WGPUFutureWaitInfo, then block with wgpuInstanceWaitAny(instance, 1, &wait, UINT64_MAX). The callback receives the adapter; hand it back through userdata1.

Copy the callback signature from WGPURequestAdapterCallback in webgpu.h. Then print adapterInfo.device and adapterInfo.backendType.

Backends

The backend argument comes from the command line: none = Dawn's choice (D3D12), -vulkan, -d3d11. Set it in Project → Properties → Debugging → Command Arguments. Running on Vulkan lets you read Dawn's output in RenderDoc with tools you already know (§7).

Checkpoint

Console shows your GPU and backend 4 (D3D12), or 6 with -vulkan. A Vulkan loader warning may also appear on D3D12: Dawn probes every backend.

§4Device and the error model

Create the device and queue with error reporting wired before anything else can fail.

  • VulkanvkCreateDevice + vkGetDeviceQueue
  • LearnWebGPUThe device
  • Header docsErrors
  • WGPUDeviceDescriptor
  • WGPURequestDeviceCallbackInfo
  • wgpuAdapterRequestDevice
  • WGPUUncapturedErrorCallback
  • WGPUDeviceLostCallback
  • WGPUDawnTogglesDescriptor
  • wgpuDeviceSetLoggingCallback
  • wgpuDeviceGetQueue

Same request/wait pattern as §3. No features or limits to request: the defaults are WebGPU's core limits, a conservative profile every adapter supports. What matters here is the error model, which replaces VkResult and validation layers:

  • A failing call still returns an object, marked invalid. Any later use of it is another error. Fix the first message, ignore the cascade.
  • Errors go to the uncaptured error callback unless captured by an error scope (wgpuDevicePushErrorScope / wgpuDevicePopErrorScope).
  • Device lost is VK_ERROR_DEVICE_LOST, but it also fires on normal destruction with reason Destroyed or CallbackCancelled. Filter those.

Chain a WGPUDawnTogglesDescriptor into the device descriptor. Toggles are Dawn-only switches passed by name:

ToggleEffect
use_user_defined_labels_in_backendYour labels become D3D12/Vulkan object names: readable RenderDoc and PIX captures.
disable_symbol_renamingWGSL identifiers survive into the generated HLSL and SPIR-V.
dump_shadersOptional. Prints generated HLSL/SPIR-V through the logging callback.
Traps
  • uncapturedErrorCallbackInfo has no mode; deviceLostCallbackInfo does. Use AllowSpontaneous.
  • Toggle names are const char*, not WGPUStringView.
  • Label everything (every descriptor has .label). Error messages and captures quote them.
Checkpoint

Non-NULL device and queue. No [gpu] errors in the console.

static void OnDeviceLost(WGPUDevice const* device, WGPUDeviceLostReason reason, WGPUStringView message,
                         void* userdata1, void* userdata2)
{
    (void)device, (void)userdata1, (void)userdata2;
    // Destroyed / CallbackCancelled: we released the device ourselves.
    if (reason == WGPUDeviceLostReason_Destroyed || reason == WGPUDeviceLostReason_CallbackCancelled)
        return;
    fprintf(stderr, "[gpu] Device lost (reason %d): %.*s\n", reason, SV(message));
}

static void OnUncapturedError(WGPUDevice const* device, WGPUErrorType type, WGPUStringView message,
                              void* userdata1, void* userdata2)
{
    (void)device, (void)userdata1, (void)userdata2;
    fprintf(stderr, "[gpu] Error (type %d): %.*s\n", type, SV(message));

    // Reported on the next tick, not inside the faulty call: the message names the call and labels.
    if (IsDebuggerPresent())
        __debugbreak();
}

static void OnLog(WGPULoggingType type, WGPUStringView message, void* userdata1, void* userdata2)
{
    (void)type, (void)userdata1, (void)userdata2;
    fprintf(stderr, "[dawn] %.*s\n", SV(message));
}

Configure (end of Gpu_Init, and Gpu_Resize)

Take caps.formats[0], the preferred format: BGRA8Unorm on D3D12. It is not sRGB, which suits Doom: its palette is already display-encoded, so bytes pass through untouched. Gpu_Resize fills a WGPUSurfaceConfiguration (device, format, RenderAttachment usage, size, Fifo, alpha Auto) and calls wgpuSurfaceConfigure. Calling it again is how you recreate the swapchain. Skip 0×0: a minimized window.

Acquire and present (Gpu_BeginFrame, Gpu_EndFrame)

WGPUSurfaceTexture.statusVulkan analogDo
SuccessOptimal, SuccessSuboptimalVK_SUCCESS, VK_SUBOPTIMAL_KHRDraw.
Outdated, LostVK_ERROR_OUT_OF_DATE_KHR, VK_ERROR_SURFACE_LOST_KHRReconfigure, skip the frame.
Timeout, ErrorVK_TIMEOUT, other errorsSkip the frame.

Create a view of the texture for the render pass. Keep the texture in gpu->frameTexture until after wgpuSurfacePresent, then release the view and the texture. End the frame with wgpuInstanceProcessEvents: it fires AllowProcessEvents callbacks, none yet, but buffer mapping in step 2 relies on it.

Record and submit (DrawFrame in main.c)

Encoder, render pass with one color attachment (loadOp = Clear, storeOp = Store), End, Finish, Submit, release what you created. No layout transition before or after the pass: Dawn knows the texture goes from render target to present.

Traps
  • WGPURenderPassColorAttachment.depthSlice must be WGPU_DEPTH_SLICE_UNDEFINED for 2D views. The _INIT macro sets it; {0} does not.
  • Call wgpuRenderPassEncoderEnd before wgpuCommandEncoderFinish, and release the pass encoder.
  • Release every returned surface texture, also on the skip paths.
Checkpoint

The window shows your clear color. Resize and minimize: no errors in the console.

void Gpu_Resize(Gpu* gpu, uint32_t width, uint32_t height)
{
    if (width == 0 || height == 0)
        return;

    gpu->width  = width;
    gpu->height = height;

    WGPUSurfaceConfiguration config = WGPU_SURFACE_CONFIGURATION_INIT;
    config.device                   = gpu->device;
    config.format                   = gpu->surfaceFormat;
    config.usage                    = WGPUTextureUsage_RenderAttachment;
    config.width                    = width;
    config.height                   = height;
    config.presentMode              = WGPUPresentMode_Fifo;
    config.alphaMode                = WGPUCompositeAlphaMode_Auto;
    wgpuSurfaceConfigure(gpu->surface, &config);
}

WGPUTextureView Gpu_BeginFrame(Gpu* gpu)
{
    WGPUSurfaceTexture surfaceTexture = WGPU_SURFACE_TEXTURE_INIT;
    wgpuSurfaceGetCurrentTexture(gpu->surface, &surfaceTexture);

    switch (surfaceTexture.status)
    {
    case WGPUSurfaceGetCurrentTextureStatus_SuccessOptimal:
    case WGPUSurfaceGetCurrentTextureStatus_SuccessSuboptimal:
        break;

    case WGPUSurfaceGetCurrentTextureStatus_Outdated:
    case WGPUSurfaceGetCurrentTextureStatus_Lost:
        if (surfaceTexture.texture)
            wgpuTextureRelease(surfaceTexture.texture);
        Gpu_Resize(gpu, gpu->width, gpu->height);
        return NULL;

    default:
        if (surfaceTexture.texture)
            wgpuTextureRelease(surfaceTexture.texture);
        return NULL;
    }

    gpu->frameTexture = surfaceTexture.texture;

    WGPUTextureViewDescriptor viewDesc = WGPU_TEXTURE_VIEW_DESCRIPTOR_INIT;
    viewDesc.label                     = Gpu_Str("Swapchain view");
    return wgpuTextureCreateView(surfaceTexture.texture, &viewDesc);
}

void Gpu_EndFrame(Gpu* gpu, WGPUTextureView view)
{
    wgpuSurfacePresent(gpu->surface);

    wgpuTextureViewRelease(view);
    wgpuTextureRelease(gpu->frameTexture);
    gpu->frameTexture = NULL;

    wgpuInstanceProcessEvents(gpu->instance);
}
Solution §5: DrawFrame
static void DrawFrame(Gpu* gpu, WGPURenderPipeline pipeline, WGPUTextureView target)
{
    (void)pipeline;  // §6

    WGPUCommandEncoderDescriptor encoderDesc = WGPU_COMMAND_ENCODER_DESCRIPTOR_INIT;
    encoderDesc.label                        = Gpu_Str("Frame encoder");

    WGPUCommandEncoder encoder = wgpuDeviceCreateCommandEncoder(gpu->device, &encoderDesc);

    WGPURenderPassColorAttachment color = WGPU_RENDER_PASS_COLOR_ATTACHMENT_INIT;
    color.view                          = target;
    color.loadOp                        = WGPULoadOp_Clear;
    color.storeOp                       = WGPUStoreOp_Store;
    color.clearValue                    = (WGPUColor){ 0.1, 0.1, 0.12, 1.0 };

    WGPURenderPassDescriptor passDesc = WGPU_RENDER_PASS_DESCRIPTOR_INIT;
    passDesc.label                    = Gpu_Str("Triangle pass");
    passDesc.colorAttachmentCount     = 1;
    passDesc.colorAttachments         = &color;

    WGPURenderPassEncoder pass = wgpuCommandEncoderBeginRenderPass(encoder, &passDesc);
    wgpuRenderPassEncoderEnd(pass);
    wgpuRenderPassEncoderRelease(pass);

    WGPUCommandBuffer commands = wgpuCommandEncoderFinish(encoder, NULL);
    wgpuQueueSubmit(gpu->queue, 1, &commands);

    wgpuCommandBufferRelease(commands);
    wgpuCommandEncoderRelease(encoder);
}

Clip space

WebGPU clip space is Y-up (D3D/GL convention), depth 0 to 1. Vulkan's is Y-down: the same vertices would render upside down there. Dawn's Vulkan backend compensates with a negative viewport height; look for it in RenderDoc.

The shader, to type in as a C string literal:

struct VsOut {
    @builtin(position) position: vec4f,
    @location(0) color: vec3f,
};

@vertex
fn vs_main(@builtin(vertex_index) i: u32) -> VsOut {
    var positions = array<vec2f, 3>(vec2f(0.0, 0.5), vec2f(-0.5, -0.5), vec2f(0.5, -0.5));
    var colors = array<vec3f, 3>(vec3f(1.0, 0.0, 0.0), vec3f(0.0, 1.0, 0.0), vec3f(0.0, 0.0, 1.0));
    var out: VsOut;
    out.position = vec4f(positions[i], 0.0, 1.0);
    out.color = colors[i];
    return out;
}

@fragment
fn fs_main(in: VsOut) -> @location(0) vec4f {
    return vec4f(in.color, 1.0);
}

Pipeline

Chain WGPUShaderSourceWGSL into the module descriptor. In the pipeline descriptor: vertex stage (module, entry point, no vertex buffers), TriangleList, a fragment stage with one color target in gpu->surfaceFormat, and layout = NULL. The auto layout is reflected from the shader, like building the VkPipelineLayout from SPIR-V reflection. Leave cull mode, front face, multisample and write mask at their _INIT defaults. Release the shader module once the pipeline exists.

In DrawFrame, inside the pass: SetPipeline, Draw(3, 1, 0, 0). Finally write Gpu_Shutdown: unconfigure the surface, then release surface, queue, device, adapter, instance.

    "    @builtin(position) position: vec4f,\n"
    "    @location(0) color: vec3f,\n"
    "};\n"
    "\n"
    "@vertex\n"
    "fn vs_main(@builtin(vertex_index) i: u32) -> VsOut {\n"
    "    var positions = array<vec2f, 3>(vec2f(0.0, 0.5), vec2f(-0.5, -0.5), vec2f(0.5, -0.5));\n"
    "    var colors = array<vec3f, 3>(vec3f(1.0, 0.0, 0.0), vec3f(0.0, 1.0, 0.0), vec3f(0.0, 0.0, 1.0));\n"
    "    var out: VsOut;\n"

    "    out.color = colors[i];\n"
    "    return out;\n"
    "}\n"
    "\n"

static WGPURenderPipeline CreateTrianglePipeline(Gpu* gpu)
{
    WGPUShaderSourceWGSL wgsl = WGPU_SHADER_SOURCE_WGSL_INIT;
    wgsl.code                 = Gpu_Str(kShaderSource);

    WGPUShaderModuleDescriptor moduleDesc = WGPU_SHADER_MODULE_DESCRIPTOR_INIT;
    moduleDesc.nextInChain                = &wgsl.chain;
    moduleDesc.label                      = Gpu_Str("Triangle shader");

    WGPUShaderModule module = wgpuDeviceCreateShaderModule(gpu->device, &moduleDesc);

    WGPUColorTargetState colorTarget = WGPU_COLOR_TARGET_STATE_INIT;
    colorTarget.format               = gpu->surfaceFormat;

    WGPUFragmentState fragment = WGPU_FRAGMENT_STATE_INIT;
    fragment.module            = module;
    fragment.entryPoint        = Gpu_Str("fs_main");
    fragment.targetCount       = 1;
    fragment.targets           = &colorTarget;

    WGPURenderPipelineDescriptor pipelineDesc = WGPU_RENDER_PIPELINE_DESCRIPTOR_INIT;
    pipelineDesc.label                        = Gpu_Str("Triangle pipeline");
    pipelineDesc.vertex.module                = module;
    pipelineDesc.vertex.entryPoint            = Gpu_Str("vs_main");
    pipelineDesc.primitive.topology           = WGPUPrimitiveTopology_TriangleList;
    pipelineDesc.fragment                     = &fragment;

    WGPURenderPipeline pipeline = wgpuDeviceCreateRenderPipeline(gpu->device, &pipelineDesc);

    wgpuShaderModuleRelease(module);
    return pipeline;
}

// DrawFrame, between BeginRenderPass and End:
wgpuRenderPassEncoderSetPipeline(pass, pipeline);

void Gpu_Shutdown(Gpu* gpu)
{
    if (gpu->surface)
    {
        wgpuSurfaceUnconfigure(gpu->surface);
        wgpuSurfaceRelease(gpu->surface);
    }
    if (gpu->queue)
        wgpuQueueRelease(gpu->queue);
    if (gpu->device)
        wgpuDeviceRelease(gpu->device);
    if (gpu->adapter)
        wgpuAdapterRelease(gpu->adapter);
    if (gpu->instance)
        wgpuInstanceRelease(gpu->instance);

    memset(gpu, 0, sizeof(*gpu));
}

§7Debugging toolkit

Break the triangle on purpose and practice each tool once. It pays back in step 3.

Read an error

Misspell the fragment entry point as "fs_mian". Real output from this Dawn build:

[gpu] Error (type 2): Entry point ""fs_mian"" doesn't exist in the shader module [ShaderModule "Triangle shader"].
 - While validating fragment stage ([ShaderModule "Triangle shader"], entryPoint: "fs_mian").
 - While validating fragment state.
 - While calling [Device "Main device"].CreateRenderPipeline([RenderPipelineDescriptor ""Triangle pipeline""]).

[gpu] Error (type 2): [Invalid RenderPipeline "Triangle pipeline"] is invalid due to a previous error.
 - While encoding [RenderPassEncoder "Triangle pass"].SetPipeline([Invalid RenderPipeline "Triangle pipeline"]).
 - While finishing [CommandEncoder "Frame encoder"].

[gpu] Error (type 2): [Invalid CommandBuffer from CommandEncoder "Frame encoder"] is invalid due to a previous error.
 - While calling [Queue].Submit([[Invalid CommandBuffer from CommandEncoder "Frame encoder"]])

Read the first error bottom-up: the API call, then the nested validation path. Everything after it is the invalid-object cascade. Encoder errors are deferred and reported at Finish, so the second message cites SetPipeline but surfaces at Finish.

Break at the right place

Errors reach the callback on the next tick (present or ProcessEvents), so a breakpoint there shows the wrong stack. To catch the faulty call, bracket the suspect code with an error scope:

wgpuDevicePushErrorScope(gpu->device, WGPUErrorFilter_Validation);
// ... suspect calls ...
wgpuDevicePopErrorScope(gpu->device, popCallbackInfo);  // WGPUPopErrorScopeCallbackInfo, returns a future
Known issue

The device toggle enable_immediate_error_handling is meant to fire the callback inside the faulty call. In this Dawn build it crashes with an access violation right after the first encoder error (found while writing this page). Don't use it.

RenderDoc on the Vulkan backend

Launch build\Debug\step1_triangle.exe with -vulkan from RenderDoc and capture a frame. Things to find:

  • The negative viewport height Dawn uses to flip Y.
  • The barriers Dawn inserted around the swapchain image.
  • Your WGSL compiled to SPIR-V by Tint, with your identifiers kept by disable_symbol_renaming.
  • Your labels on the pipeline and pass (use_user_defined_labels_in_backend).

Without -vulkan you capture D3D12 instead; PIX works there too.

Vulkan validation layers under Dawn

With -vulkan, set VK_LOADER_LAYERS_ENABLE=*validation in Debugging → Environment, or use vkconfig. This validates Dawn's Vulkan usage, not yours: useful to see what WebGPU's validation already prevents. Expected noise, from Dawn itself at adapter setup: VUID-VkPhysicalDeviceProperties2-pNext-pNext, a VkPhysicalDeviceMaintenance9FeaturesKHR chained into a properties query. A Dawn bug, not yours.

Compile WGSL offline with tint.exe

third_party\dawn\bin\tint.exe --format spvasm --entry-point vs_main triangle.wgsl
third_party\dawn\bin\tint.exe --format hlsl   --entry-point vs_main triangle.wgsl

The HLSL shows a WebGPU guarantee you get for free: out-of-bounds access is impossible, so Tint clamps your dynamic index.

v.position = float4(positions[min(i, 2u)], 0.0f, 1.0f);
v.color = colors[min(i, 2u)];
