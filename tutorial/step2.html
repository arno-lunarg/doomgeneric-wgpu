Doom frame on the GPU

Doom renders on the CPU into a 320×200 buffer. Upload it to a texture each frame; draw it into a 4:3 viewport with one triangle. New objects: texture, sampler, bind group layout, pipeline layout, bind group.

You write: the TODOs in src/doom/doomgeneric_wgpu.c, shaders/doom_blit.wgsl, a gpu.c refactor. Target: pixel-identical to the GDI blit (§6).

Make Gpu generic

Gpu_Init builds the triangle pipeline into Gpu.render_pipeline; Doom links the same gpu.c. Move it to CreateTrianglePipeline in step1_triangle/main.c; remove the field.

Gpu_Resize fixes:

  1. && → ||. A W×0 window is possible; configuring it is an error.
  2. Store gpu->width, gpu->height. The Outdated path in Gpu_BeginFrame reconfigures with them; they stay 0, so it never recovers.
  3. Usage: RenderAttachment only. StorageBinding on BGRA8Unorm requires WGPUFeatureName_BGRA8UnormStorage (webgpu.h:598), not requested. TextureBinding is unused.
Your #CLAUDE question: wgpuDeviceTick in Gpu_EndFrame

Redundant. wgpuInstanceProcessEvents → InstanceBase::ProcessEvents → APITick() on every device (src/dawn/native/Instance.cpp, pinned commit). wgpuDeviceTick is Dawn-only. Remove it.

Wire it into Doom

  • DG_Init: Gpu_Init with g_platform handles, size, ParseBackend(); then atexit(ShutdownGpu). Doom exits via exit() from several paths; atexit covers all.
  • DG_DrawFrame: on g_platform.resized, clear the flag, Gpu_Resize.
  • DrawGpu: begin frame, clear pass (black), submit, end frame, return true.
Traps
  • Gpu_BeginFrame returns NULL: still return true. A configured flip-model swapchain hides GDI output.
  • Doom objects stay out of Gpu: statics in doomgeneric_wgpu.c. gpu.c is shared with step 1.
Checkpoint

Black window, no [gpu] errors, also after resize and minimize. step1_triangle and -gdi unchanged.

Solution §1: gpu.c and step 1
// gpu.c: Gpu_Init ends after the surface format block. No pipeline here.
void Gpu_Resize(Gpu* gpu, uint32_t width, uint32_t height)
{
    if (width == 0 || height == 0) {
        return;
    }

    gpu->width = width;
    gpu->height = height;

    WGPUSurfaceConfiguration config = WGPU_SURFACE_CONFIGURATION_INIT;
    config.device = gpu->device;
    config.format = gpu->surfaceFormat;
    config.usage = WGPUTextureUsage_RenderAttachment;
    config.width = width;
    config.height = height;
    config.presentMode = WGPUPresentMode_Immediate;

    wgpuSurfaceConfigure(gpu->surface, &config);
}

void Gpu_Shutdown(Gpu* gpu)
{
    wgpuSurfaceUnconfigure(gpu->surface);
    wgpuSurfaceRelease(gpu->surface);
    wgpuQueueRelease(gpu->queue);
    wgpuDeviceRelease(gpu->device);
    wgpuAdapterRelease(gpu->adapter);
    wgpuInstanceRelease(gpu->instance);
}
// step1_triangle/main.c (#include "shader.h"); DrawFrame uses `pipeline`, not gpu->render_pipeline.
static WGPURenderPipeline CreateTrianglePipeline(Gpu* gpu)
{
    WGPUShaderModule module = Shader_Load(gpu->device, "triangle.wgsl");

    WGPUColorTargetState colorTarget = WGPU_COLOR_TARGET_STATE_INIT;
    colorTarget.format = gpu->surfaceFormat;

    WGPUFragmentState fragment = WGPU_FRAGMENT_STATE_INIT;
    fragment.module = module;
    fragment.entryPoint = Gpu_Str("fs_main");
    fragment.targetCount = 1;
    fragment.targets = &colorTarget;

    WGPURenderPipelineDescriptor desc = WGPU_RENDER_PIPELINE_DESCRIPTOR_INIT;
    desc.label = Gpu_Str("Triangle pipeline");
    desc.vertex.module = module;
    desc.vertex.entryPoint = Gpu_Str("vs_main");
    desc.primitive.topology = WGPUPrimitiveTopology_TriangleList;
    desc.fragment = &fragment;

    WGPURenderPipeline pipeline = wgpuDeviceCreateRenderPipeline(gpu->device, &desc);
    Shader_Free(module);
    return pipeline;
}

static bool DrawGpu(void)
{
    WGPUTextureView target = Gpu_BeginFrame(&s_gpu);
    if (!target)
        return true;

    WGPUCommandEncoderDescriptor encoderDesc = WGPU_COMMAND_ENCODER_DESCRIPTOR_INIT;
    encoderDesc.label                        = Gpu_Str("Doom frame encoder");

    WGPUCommandEncoder encoder = wgpuDeviceCreateCommandEncoder(s_gpu.device, &encoderDesc);

    WGPURenderPassColorAttachment color = WGPU_RENDER_PASS_COLOR_ATTACHMENT_INIT;
    color.view                          = target;
    color.loadOp                        = WGPULoadOp_Clear;
    color.storeOp                       = WGPUStoreOp_Store;
    color.clearValue                    = (WGPUColor){ 0.0, 0.0, 0.0, 1.0 };

    WGPURenderPassDescriptor passDesc = WGPU_RENDER_PASS_DESCRIPTOR_INIT;
    passDesc.label                    = Gpu_Str("Doom blit pass");
    passDesc.colorAttachmentCount     = 1;
    passDesc.colorAttachments         = &color;

    WGPURenderPassEncoder pass = wgpuCommandEncoderBeginRenderPass(encoder, &passDesc);
    wgpuRenderPassEncoderEnd(pass);
    wgpuRenderPassEncoderRelease(pass);

    WGPUCommandBuffer commands = wgpuCommandEncoderFinish(encoder, NULL);
    wgpuQueueSubmit(s_gpu.queue, 1, &commands);

    wgpuCommandBufferRelease(commands);
    wgpuCommandEncoderRelease(encoder);

    Gpu_EndFrame(&s_gpu, target);
    return true;
}

static void ShutdownGpu(void)
{
    Gpu_Shutdown(&s_gpu);
}

§2Frame texture

Create a 320×200 texture that Doom's frame can be copied into and sampled from.

  • VulkanvkCreateImage + vkAllocateMemory + vkCreateImageView
  • LearnWebGPUA first texture
  • SpecGPUTextureDescriptor
  • WGPUTextureDescriptor
  • wgpuDeviceCreateTexture
  • wgpuTextureCreateView
  • WGPUTextureFormat_BGRA8Unorm
  • WGPUTextureUsage_TextureBinding
  • WGPUTextureUsage_CopyDst

No memory allocation. Dawn derives memory and layouts from the usage flags and validates every use against them. Here: CopyDst (upload), TextureBinding (sampling).

Format: DG_ScreenBuffer is uint32_t 0x00RRGGBB, i.e. bytes B, G, R, 0: BGRA8Unorm. RGBA8Unorm swaps red and blue. No sRGB: the palette is display-encoded and the surface is BGRA8Unorm; bytes pass through.

WGPU_TEXTURE_DESCRIPTOR_INIT (webgpu.h:4053): dimension Undefined (= 2D), 1 mip, 1 sample, size {0, 1, 1}: set the width. Keep texture and view in statics; wgpuTextureCreateView(texture, NULL) views the whole texture. §4 binds the view.

Traps
  • Alpha is 0. Nothing may read it: no blending; the shader writes 1 (§4).
  • Textures are zero-initialized (Dawn clears lazily). An unwritten texture samples black, not garbage.
Checkpoint

No errors. Still black.

§3Upload

Copy DG_ScreenBuffer into the texture every frame.

  • Vulkanstaging buffer + vkCmdCopyBufferToImage + barriers
  • SpecGPUQueue.writeTexture
  • wgpuQueueWriteTexture
  • WGPUTexelCopyTextureInfo
  • WGPUTexelCopyBufferLayout
  • WGPUExtent3D

Replaces staging buffer, memcpy, copy command and barriers (webgpu.h:4947):

  • Data copied during the call. DG_ScreenBuffer is reusable on return.
  • Queue-ordered: after earlier submits, before later ones. Call it before the submit that samples. Dawn resolves the hazard with the previous frame's reads: no staging ring, no double buffering.

Layout: bytesPerRow = 320 * 4 = 1280, rowsPerImage = 200, 256000 bytes. WGPU_TEXEL_COPY_BUFFER_LAYOUT_INIT: bytesPerRow = WGPU_COPY_STRIDE_UNDEFINED, valid for one row only. WGPU_TEXEL_COPY_TEXTURE_INFO_INIT: mip 0, origin 0, aspect All.

Traps
  • The 256-byte bytesPerRow alignment applies to encoder buffer-to-texture copies, not writeTexture. 1280 = 5×256 anyway.
  • Queue only; no encoder variant. Called after wgpuQueueSubmit: one frame of latency.
Checkpoint

No errors. Still black: nothing samples yet. A capture shows the texture filled (§6).

Shader: shaders/doom_blit.wgsl

No vertex buffer. From vertex_index 0, 1, 2: uv (0,0), (2,0), (0,2); clip position (2u − 1, 1 − 2v). Inside the viewport uv spans 0…1, v down like texture rows. Fragment: sample, alpha 1.

GLSL (Vulkan)WGSL
layout(set = 0, binding = 0)@group(0) @binding(0)
uniform texture2D t; + uniform sampler s;var t: texture_2d<f32>; + var s: sampler;. No combined image samplers.
texture(sampler2D(t, s), uv)textureSample(t, s, uv)
texelFetch(t, ivec2(p), 0)textureLoad(t, vec2i(p), 0), no sampler (step 2b)

Texture origin: top-left, as in Vulkan. Clip space: Y-up (step 1), hence 1 − 2v.

Uniformity

textureSample uses implicit derivatives: WGSL requires uniform control flow and enforces it at compile time (GLSL: undefined behavior). Tint, sample inside if (in.uv.x > 0.5):

error: 'textureSample' must only be called from uniform control flow
        return textureSample(frame, frameSampler, in.uv);
note: control flow depends on possibly non-uniform value
    if (in.uv.x > 0.5) {
note: parameter 'in' of 'fs_main' may be non-uniform

Fix: sample before branching, or use textureSampleLevel / textureLoad.

Sampler

Nearest, clamp to edge. WGPU_SAMPLER_DESCRIPTOR_INIT (webgpu.h:3867): all modes Undefined = default = nearest, clamp; a NULL descriptor is equivalent. Set them explicitly anyway. Scale is 3× by 3.6×: rows are 3 or 4 pixels, as with GDI COLORONCOLOR. Try linear once.

Layouts

Two bindings, fragment visibility: 0 = texture (Float, 2D), 1 = sampler (Filtering). Pipeline layout: that one bind group layout. Pipeline: as in step 1, plus layout and the new shader.

Trap: binding type = filled sub-struct

WGPU_BIND_GROUP_LAYOUT_ENTRY_INIT (webgpu.h:3457) zero-fills buffer, sampler, texture, storageTexture; 0 = BindingNotUsed. Fill exactly one; set visibility (default None). Sub-struct _INIT macros use Undefined = default (Float, 2D, Filtering). Sampler type left unset:

[gpu] Error (type 2): BindGroupLayoutEntry had none of buffer, sampler, texture, storageTexture, texelBuffer, or externalTexture set
 - While validating entries[1]
 - While validating [BindGroupLayoutDescriptor ""Doom frame layout""]
 - While calling [Device "MyGpu"].CreateBindGroupLayout([BindGroupLayoutDescriptor ""Doom frame layout""]).
Auto layout

layout = NULL reflects it from WGSL; wgpuRenderPipelineGetBindGroupLayout(pipeline, 0) (webgpu.h:5005) returns it. Such a layout is tied to its pipeline: its bind groups are incompatible with any other pipeline, even an identical one. Use explicit layouts; step 3 shares them across pipelines.

Bind group

Entries: 0 → textureView, 1 → sampler. Immutable at creation; no pool, no update. The bind group references view and sampler; the pipeline references its layouts. Release shader module, pipeline layout and bind group layout after creation.

Solution §4: doom_blit.wgsl
// Doom's 320x200 frame, stretched over the viewport by one fullscreen triangle.

@group(0) @binding(0) var frame: texture_2d<f32>;
@group(0) @binding(1) var frameSampler: sampler;

struct VsOut {
    @builtin(position) position: vec4f,
    @location(0) uv: vec2f,
};

// Vertex 0, 1, 2 -> uv (0,0), (2,0), (0,2) -> clip (-1,1), (3,1), (-1,-3).
// The triangle overhangs the viewport; the visible part has uv in [0,1], v down like the texture.
@vertex
fn vs_main(@builtin(vertex_index) i: u32) -> VsOut {
    let uv = vec2f(f32((i << 1u) & 2u), f32(i & 2u));
    var out: VsOut;
    out.position = vec4f(uv.x * 2.0 - 1.0, 1.0 - uv.y * 2.0, 0.0, 1.0);
    out.uv = uv;
    return out;
}

// DG_ScreenBuffer alpha is 0: force 1.
@fragment
fn fs_main(in: VsOut) -> @location(0) vec4f {
    return vec4f(textureSample(frame, frameSampler, in.uv).rgb, 1.0);
}

§5Draw

Doom in the window, 4:3, black bars, identical to -gdi.

  • VulkanvkCmdSetViewport + vkCmdBindDescriptorSets + vkCmdDraw
  • SpecsetViewport
  • wgpuRenderPassEncoderSetViewport
  • wgpuRenderPassEncoderSetPipeline
  • wgpuRenderPassEncoderSetBindGroup
  • wgpuRenderPassEncoderDraw

In the pass: viewport from LetterboxRect (client pixels; 1280×720 → 160, 0, 960, 720), depth 0–1. Origin top-left, y down, as Vulkan with positive height; Dawn flips on Vulkan. Then pipeline, bind group 0 (no dynamic offsets), Draw(3, 1, 0, 0). Clipping trims the triangle; the clear color fills the bars.

ShutdownGpu: release bind group, pipeline, sampler, view, texture; then Gpu_Shutdown.

Traps
  • The viewport must fit the render target. LetterboxRect reads g_platform: call Gpu_Resize before DrawGpu, else a shrinking window gives an oversized viewport and a validation error.
  • Viewport is per pass; BeginRenderPass resets it.
Checkpoint

Prove pixel equality; break it twice; catch each error at its source.

Read a usage error

Remove CopyDst from the texture usage. Output, every frame:

[gpu] Error (type 2): Usage (TextureUsage::TextureBinding) of [Texture "Doom frame"] does not include TextureUsage::CopyDst.
 - While calling [Queue "MyQueue"].WriteTexture([TexelCopyTextureInfo texture: [Texture "Doom frame"], mipLevel: 0, origin: [Origin3D x:0, y:0, z:0], aspect: TextureAspect::Undefined], (256000 bytes), [TexelCopyBufferLayout offset:0, bytesPerRow:1280, rowsPerImage:200], [Extent3D width:320, height:200, depthOrArrayLayers:1])

Window stays black: the texture is valid and zero-filled; only the writes fail. Contrast §4: one invalid layout invalidates pipeline layout, pipeline, bind group and every command buffer.

Catch errors at the source with an error scope

Wrap CreateFrameResources() in a validation scope, popped synchronously: wgpuDevicePushErrorScope (WGPUErrorFilter_Validation), then wgpuDevicePopErrorScope in WaitAnyOnly mode and wgpuInstanceWaitAny on its future, as for the adapter. Callback: WGPUPopErrorScopeCallback (webgpu.h:1325). Sampler type removed again:

[scope CreateFrameResources] BindGroupLayoutEntry had none of buffer, sampler, texture, storageTexture, texelBuffer, or externalTexture set
 - While validating entries[1]
 - While validating [BindGroupLayoutDescriptor ""Doom frame layout""]
 - While calling [Device "MyGpu"].CreateBindGroupLayout([BindGroupLayoutDescriptor ""Doom frame layout""]).

[gpu] Error (type 2): [Invalid RenderPipeline "Doom blit pipeline"] is invalid due to a previous error.
 - While encoding [RenderPassEncoder "Doom blit pass"].SetPipeline([Invalid RenderPipeline "Doom blit pipeline"]).

A scope keeps its first error and discards the rest: the creation cascade is gone. Per-frame errors outside it still reach the uncaptured callback. A breakpoint in the pop callback stops next to the faulty code, not at the next present.

Solution §6: error scope helper
static void OnPopErrorScope(WGPUPopErrorScopeStatus status, WGPUErrorType type, WGPUStringView message,
                            void* userdata1, void* userdata2)
{
    (void)userdata2;
    if (status == WGPUPopErrorScopeStatus_Success && type != WGPUErrorType_NoError)
        fprintf(stderr, "[scope %s] %.*s\n", (const char*)userdata1, (int)message.length, message.data);
}

// Blocks until everything since the push is validated. Debugging only.
static void PopErrorScope(const char* what)
{
    WGPUPopErrorScopeCallbackInfo info = WGPU_POP_ERROR_SCOPE_CALLBACK_INFO_INIT;
    info.mode                          = WGPUCallbackMode_WaitAnyOnly;
    info.callback                      = OnPopErrorScope;
    info.userdata1                     = (void*)what;

    WGPUFutureWaitInfo wait = WGPU_FUTURE_WAIT_INFO_INIT;
    wait.future             = wgpuDevicePopErrorScope(s_gpu.device, info);
    wgpuInstanceWaitAny(s_gpu.instance, 1, &wait, UINT64_MAX);
}

RenderDoc: where did writeTexture go?

Capture a frame with -vulkan. Find:

  • The wgpuQueueWriteTexture copy: buffer-to-image from Dawn's staging memory, with barriers, before your pass.
  • The descriptor set from your bind group: sampled image, sampler, your bindings.
