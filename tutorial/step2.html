Doom frame on the GPU

Doom still renders on the CPU into a 320×200 buffer. You copy it into a texture every frame and stretch it over a 4:3 viewport with one triangle. New objects: texture, sampler, bind group layout, pipeline layout, bind group.

You write the TODOs in src/doom/doomgeneric_wgpu.c, a new shaders/doom_blit.wgsl, and a small refactor of gpu.c. The result must match the GDI blit pixel for pixel; §6 proves it.

§0Setup

Set doom_wgpu as startup project and press F5. It runs from wad/, which now holds DOOM.WAD from your Steam install (Ultimate Doom). Doom's IWAD search tries doom.wad before freedoom1.wad. With every TODO empty, Doom runs and shows through the GDI fallback.

Make Gpu generic

Your Gpu_Init builds the triangle pipeline from triangle.wgsl and stores it in Gpu.render_pipeline. Doom links the same gpu.c. Move that block into CreateTrianglePipeline in step1_triangle/main.c, which already returns a pipeline to DrawFrame, and remove the field.

Three fixes in Gpu_Resize before a resizable game window relies on it:

  1. width == 0 && height == 0 should be ||. A window dragged to zero height is W×0, and configuring 0 height is an error.
  2. Store gpu->width and gpu->height. The Outdated path in Gpu_BeginFrame reconfigures with them; today they stay 0, so it never recovers.
  3. Usage: only RenderAttachment. StorageBinding on a BGRA8Unorm surface needs the optional feature WGPUFeatureName_BGRA8UnormStorage (webgpu.h:598), which you do not request. Ask for what you use.
Your #CLAUDE question: wgpuDeviceTick in Gpu_EndFrame

Redundant. In Dawn at the pinned commit, wgpuInstanceProcessEvents calls InstanceBase::ProcessEvents, which calls APITick() on every device before flushing callbacks (src/dawn/native/Instance.cpp). wgpuDeviceTick is Dawn-only; ProcessEvents is the portable call. Drop the tick.

Wire it into Doom

DG_Init: Gpu_Init on g_platform.hinstance / hwnd / size with ParseBackend(), then atexit(ShutdownGpu). Doom leaves through exit() from several places (window close, quit menu, I_Error), so atexit is the one hook that always runs. DG_DrawFrame: on g_platform.resized, clear the flag and call Gpu_Resize. DrawGpu: begin frame, encoder, one pass clearing to black, end, finish, submit, end frame, return true.

Traps
  • When Gpu_BeginFrame returns NULL, return true anyway. The flip-model swapchain owns the window once configured: a GDI blit for that frame would not show.
  • Keep Doom-specific objects out of Gpu. They live as statics in doomgeneric_wgpu.c; gpu.c stays shared with step 1.
Checkpoint

Black Doom window, no [gpu] errors. Resize and minimize: still no errors. step1_triangle still draws its triangle. -gdi still shows Doom.

Solution §1: gpu.c and step 1
// gpu.c: Gpu_Init ends after the surface format block. No pipeline here.
void Gpu_Resize(Gpu* gpu, uint32_t width, uint32_t height)
{
    if (width == 0 || height == 0) {
        return;
    }

    gpu->width = width;
    gpu->height = height;

    WGPUSurfaceConfiguration config = WGPU_SURFACE_CONFIGURATION_INIT;
    config.device = gpu->device;
    config.format = gpu->surfaceFormat;
    config.usage = WGPUTextureUsage_RenderAttachment;
    config.width = width;
    config.height = height;
    config.presentMode = WGPUPresentMode_Immediate;

    wgpuSurfaceConfigure(gpu->surface, &config);
}

void Gpu_Shutdown(Gpu* gpu)
{
    wgpuSurfaceUnconfigure(gpu->surface);
    wgpuSurfaceRelease(gpu->surface);
    wgpuQueueRelease(gpu->queue);
    wgpuDeviceRelease(gpu->device);
    wgpuAdapterRelease(gpu->adapter);
    wgpuInstanceRelease(gpu->instance);
}
// step1_triangle/main.c (#include "shader.h"); DrawFrame uses `pipeline`, not gpu->render_pipeline.
static WGPURenderPipeline CreateTrianglePipeline(Gpu* gpu)
{
    WGPUShaderModule module = Shader_Load(gpu->device, "triangle.wgsl");

    WGPUColorTargetState colorTarget = WGPU_COLOR_TARGET_STATE_INIT;
    colorTarget.format = gpu->surfaceFormat;

    WGPUFragmentState fragment = WGPU_FRAGMENT_STATE_INIT;
    fragment.module = module;
    fragment.entryPoint = Gpu_Str("fs_main");
    fragment.targetCount = 1;
    fragment.targets = &colorTarget;

    WGPURenderPipelineDescriptor desc = WGPU_RENDER_PIPELINE_DESCRIPTOR_INIT;
    desc.label = Gpu_Str("Triangle pipeline");
    desc.vertex.module = module;
    desc.vertex.entryPoint = Gpu_Str("vs_main");
    desc.primitive.topology = WGPUPrimitiveTopology_TriangleList;
    desc.fragment = &fragment;

    WGPURenderPipeline pipeline = wgpuDeviceCreateRenderPipeline(gpu->device, &desc);
    Shader_Free(module);
    return pipeline;
}

static bool DrawGpu(void)
{
    WGPUTextureView target = Gpu_BeginFrame(&s_gpu);
    if (!target)
        return true;

    WGPUCommandEncoderDescriptor encoderDesc = WGPU_COMMAND_ENCODER_DESCRIPTOR_INIT;
    encoderDesc.label                        = Gpu_Str("Doom frame encoder");

    WGPUCommandEncoder encoder = wgpuDeviceCreateCommandEncoder(s_gpu.device, &encoderDesc);

    WGPURenderPassColorAttachment color = WGPU_RENDER_PASS_COLOR_ATTACHMENT_INIT;
    color.view                          = target;
    color.loadOp                        = WGPULoadOp_Clear;
    color.storeOp                       = WGPUStoreOp_Store;
    color.clearValue                    = (WGPUColor){ 0.0, 0.0, 0.0, 1.0 };

    WGPURenderPassDescriptor passDesc = WGPU_RENDER_PASS_DESCRIPTOR_INIT;
    passDesc.label                    = Gpu_Str("Doom blit pass");
    passDesc.colorAttachmentCount     = 1;
    passDesc.colorAttachments         = &color;

    WGPURenderPassEncoder pass = wgpuCommandEncoderBeginRenderPass(encoder, &passDesc);
    wgpuRenderPassEncoderEnd(pass);
    wgpuRenderPassEncoderRelease(pass);

    WGPUCommandBuffer commands = wgpuCommandEncoderFinish(encoder, NULL);
    wgpuQueueSubmit(s_gpu.queue, 1, &commands);

    wgpuCommandBufferRelease(commands);
    wgpuCommandEncoderRelease(encoder);

    Gpu_EndFrame(&s_gpu, target);
    return true;
}

static void ShutdownGpu(void)
{
    Gpu_Shutdown(&s_gpu);
}

§2Frame texture

Create a 320×200 texture that Doom's frame can be copied into and sampled from.

  • VulkanvkCreateImage + vkAllocateMemory + vkCreateImageView
  • LearnWebGPUA first texture
  • SpecGPUTextureDescriptor
  • WGPUTextureDescriptor
  • wgpuDeviceCreateTexture
  • wgpuTextureCreateView
  • WGPUTextureFormat_BGRA8Unorm
  • WGPUTextureUsage_TextureBinding
  • WGPUTextureUsage_CopyDst

One call, no memory. Dawn picks memory and layouts from the usage flags and validates every later use against them: CopyDst for the upload, TextureBinding for sampling. That is all this texture does.

Format: DG_ScreenBuffer is uint32_t 0x00RRGGBB, so the bytes in memory are B, G, R, 0. That is BGRA8Unorm. RGBA8Unorm swaps red and blue. Not sRGB: Doom's palette is already display-encoded and the surface is BGRA8Unorm, so bytes pass through unchanged.

WGPU_TEXTURE_DESCRIPTOR_INIT (webgpu.h:4053): dimension Undefined (means 2D), one mip, one sample, size = {0, 1, 1}. Set the width. Store the texture and a view (wgpuTextureCreateView(texture, NULL): whole texture, same format) in statics; §4 binds the view.

Traps
  • Alpha is 0 in every pixel. Nothing may read it: no blending, and the shader writes alpha 1 (§4).
  • Textures start zero-filled. WebGPU guarantees it (Dawn clears lazily on first use). An unwritten texture samples black, never garbage.
Checkpoint

No errors. Still black.

§3Upload

Copy DG_ScreenBuffer into the texture every frame.

  • Vulkanstaging buffer + vkCmdCopyBufferToImage + barriers
  • SpecGPUQueue.writeTexture
  • wgpuQueueWriteTexture
  • WGPUTexelCopyTextureInfo
  • WGPUTexelCopyBufferLayout
  • WGPUExtent3D

One call replaces the staging buffer, the memcpy, the copy command and both barriers (webgpu.h:4947). Two properties make it simple:

  • The bytes are copied during the call. Doom may overwrite DG_ScreenBuffer as soon as it returns.
  • It is ordered on the queue: after earlier submits, before later ones. Call it before the submit that samples the texture. If last frame's draw still reads the texture on the GPU, Dawn handles the hazard. No per-frame-in-flight staging ring, no double-buffered texture.

Layout: bytesPerRow = 320 * 4 = 1280, rowsPerImage = 200, size 256000 bytes. WGPU_TEXEL_COPY_BUFFER_LAYOUT_INIT leaves bytesPerRow as WGPU_COPY_STRIDE_UNDEFINED, which is only valid for a single row. WGPU_TEXEL_COPY_TEXTURE_INFO_INIT gives mip 0, origin 0, aspect All.

Traps
  • The 256-byte bytesPerRow alignment applies to buffer-to-texture copies recorded in an encoder, not to writeTexture. Here 1280 happens to be 5×256 anyway.
  • There is no encoder version of this call. Calling it after wgpuQueueSubmit shows each frame one frame late.
Checkpoint

No errors, still black: nothing samples the texture yet. A capture already shows Doom in it (§6).

Shader: shaders/doom_blit.wgsl

No vertex buffer. Derive uv from vertex_index: vertices 0, 1, 2 get uv (0,0), (2,0), (0,2), and clip position (2u − 1, 1 − 2v). The triangle covers the viewport with uv 0…1 inside it, v pointing down like texture rows. The fragment stage samples and writes alpha 1.

GLSL (Vulkan)WGSL
layout(set = 0, binding = 0)@group(0) @binding(0)
uniform texture2D t; + uniform sampler s;var t: texture_2d<f32>; + var s: sampler;. No combined image samplers.
texture(sampler2D(t, s), uv)textureSample(t, s, uv)
texelFetch(t, ivec2(p), 0)textureLoad(t, vec2i(p), 0), no sampler (step 2b)

Texture coordinates start top-left, as in Vulkan. Clip space is Y-up (step 1), hence 1 − 2v.

Uniformity

textureSample takes implicit derivatives, so WGSL requires it in uniform control flow and checks this at compile time. GLSL leaves it undefined. Real Tint output for a sample inside if (in.uv.x > 0.5):

error: 'textureSample' must only be called from uniform control flow
        return textureSample(frame, frameSampler, in.uv);
note: control flow depends on possibly non-uniform value
    if (in.uv.x > 0.5) {
note: parameter 'in' of 'fs_main' may be non-uniform

Sample first and branch on the result, or use textureSampleLevel / textureLoad.

Sampler

Nearest filtering, clamp to edge. In WGPU_SAMPLER_DESCRIPTOR_INIT (webgpu.h:3867) every mode is Undefined, which means the default: nearest and clamp. A NULL descriptor gives the same sampler; set the fields anyway so the intent is visible. The window is 3× wide and 3.6× tall, so rows come out 3 or 4 pixels high, exactly like GDI's COLORONCOLOR. Try linear once to see the difference.

Layouts

Two bindings, both visible to the fragment stage: 0 = texture (sample type Float, view dimension 2D), 1 = sampler (Filtering). Then a pipeline layout with that one bind group layout, and the pipeline from step 1 with layout set and your new shader.

Trap: the entry's binding type is the sub-struct you fill

WGPU_BIND_GROUP_LAYOUT_ENTRY_INIT (webgpu.h:3457) zero-fills buffer, sampler, texture, storageTexture. Zero is BindingNotUsed. Fill exactly one, and set visibility (default None). The sub-struct _INIT macros use Undefined instead, meaning "default" (Float, 2D, Filtering). Forget the sampler's type and you get:

[gpu] Error (type 2): BindGroupLayoutEntry had none of buffer, sampler, texture, storageTexture, texelBuffer, or externalTexture set
 - While validating entries[1]
 - While validating [BindGroupLayoutDescriptor ""Doom frame layout""]
 - While calling [Device "MyGpu"].CreateBindGroupLayout([BindGroupLayoutDescriptor ""Doom frame layout""]).
Auto layout

layout = NULL reflects the layout from WGSL, and wgpuRenderPipelineGetBindGroupLayout(pipeline, 0) (webgpu.h:5005) returns it. Fine for one pipeline, but that layout belongs to its pipeline: bind groups made from it do not work with another pipeline, even an identical one. Write the explicit one here; it is what you will share between pipelines in step 3.

Bind group

Entries: binding 0 → textureView, binding 1 → sampler. No pool, no update call: the bind group is complete and immutable at creation. It holds references to the view and sampler; the pipeline holds its layouts. Release the shader module, pipeline layout and bind group layout right after creating the pipeline and bind group.

Solution §4: doom_blit.wgsl
// Doom's 320x200 frame, stretched over the viewport by one fullscreen triangle.

@group(0) @binding(0) var frame: texture_2d<f32>;
@group(0) @binding(1) var frameSampler: sampler;

struct VsOut {
    @builtin(position) position: vec4f,
    @location(0) uv: vec2f,
};

// Vertex 0, 1, 2 -> uv (0,0), (2,0), (0,2) -> clip (-1,1), (3,1), (-1,-3).
// The triangle overhangs the viewport; the visible part has uv in [0,1], v down like the texture.
@vertex
fn vs_main(@builtin(vertex_index) i: u32) -> VsOut {
    let uv = vec2f(f32((i << 1u) & 2u), f32(i & 2u));
    var out: VsOut;
    out.position = vec4f(uv.x * 2.0 - 1.0, 1.0 - uv.y * 2.0, 0.0, 1.0);
    out.uv = uv;
    return out;
}

// DG_ScreenBuffer alpha is 0: force 1.
@fragment
fn fs_main(in: VsOut) -> @location(0) vec4f {
    return vec4f(textureSample(frame, frameSampler, in.uv).rgb, 1.0);
}

§5Draw

Doom in the window, 4:3, black bars, identical to -gdi.

  • VulkanvkCmdSetViewport + vkCmdBindDescriptorSets + vkCmdDraw
  • SpecsetViewport
  • wgpuRenderPassEncoderSetViewport
  • wgpuRenderPassEncoderSetPipeline
  • wgpuRenderPassEncoderSetBindGroup
  • wgpuRenderPassEncoderDraw

Inside the pass: LetterboxRect gives x, y, w, h in client pixels (1280×720 → 160, 0, 960, 720). WebGPU viewport coordinates start top-left with y down, like Vulkan with a positive height; Dawn adds the flip on its Vulkan backend. Depth range 0 to 1. Then pipeline, bind group 0 with no dynamic offsets, Draw(3, 1, 0, 0). Clipping to the viewport trims the oversized triangle; the clear color fills the bars.

Finish ShutdownGpu: release bind group, pipeline, sampler, view, texture, then Gpu_Shutdown.

Traps
  • The viewport must lie inside the render target. LetterboxRect reads g_platform, so Gpu_Resize must run before DrawGpu in the same frame, or a shrinking window yields a viewport larger than the swapchain texture and a validation error.
  • Viewport is per pass: every BeginRenderPass resets it to the full attachment.
Checkpoint

Doom plays on D3D12 and with -vulkan. Resize: bars follow, picture stays 4:3. §6 checks it against -gdi.

§6Debugging toolkit

Prove the GPU path is pixel-exact, then break it twice and catch each error where it happens.

Pixel diff against -gdi

Capture both paths on the title screen (it stays up a few seconds), client area only, and compare:

pwsh -File tools/capture.ps1 -Exe build\Debug\doom_wgpu.exe -WorkDir wad -Wait 3 -Client -Out gpu.png
pwsh -File tools/capture.ps1 -Exe build\Debug\doom_wgpu.exe -WorkDir wad -Wait 3 -Client -Out gdi.png -Args -gdi
pwsh -File tools/imgdiff.ps1 -A gpu.png -B gdi.png -Out diff.png

The reference solution prints Identical (960x720) on D3D12 and on -vulkan. Without -Client, the title bar differs (focus state) and thousands of pixels mismatch in rows 0–30. If yours differs inside the picture, open diff.png: red pixels mark the mismatches. Linear filtering, an off-by-one viewport, or swapped red/blue each leave a distinct pattern.

Read a usage error

Remove CopyDst from the texture usage. Real output, repeated every frame:

[gpu] Error (type 2): Usage (TextureUsage::TextureBinding) of [Texture "Doom frame"] does not include TextureUsage::CopyDst.
 - While calling [Queue "MyQueue"].WriteTexture([TexelCopyTextureInfo texture: [Texture "Doom frame"], mipLevel: 0, origin: [Origin3D x:0, y:0, z:0], aspect: TextureAspect::Undefined], (256000 bytes), [TexelCopyBufferLayout offset:0, bytesPerRow:1280, rowsPerImage:200], [Extent3D width:320, height:200, depthOrArrayLayers:1])

The window stays black: the texture is still valid and zero-filled; only each write fails. Compare with the bind group layout error in §4, where one invalid object poisons the layout, pipeline, bind group and every frame's command buffer.

Catch errors at the source with an error scope

Bracket CreateFrameResources() in DG_Init with a validation error scope and pop it synchronously: wgpuDevicePushErrorScope with WGPUErrorFilter_Validation, then wgpuDevicePopErrorScope with a WGPUPopErrorScopeCallbackInfo in WaitAnyOnly mode and wgpuInstanceWaitAny on its future (same pattern as the adapter request). Callback type: WGPUPopErrorScopeCallback, webgpu.h:1325. With the sampler type removed again, real output:

[scope CreateFrameResources] BindGroupLayoutEntry had none of buffer, sampler, texture, storageTexture, texelBuffer, or externalTexture set
 - While validating entries[1]
 - While validating [BindGroupLayoutDescriptor ""Doom frame layout""]
 - While calling [Device "MyGpu"].CreateBindGroupLayout([BindGroupLayoutDescriptor ""Doom frame layout""]).

[gpu] Error (type 2): [Invalid RenderPipeline "Doom blit pipeline"] is invalid due to a previous error.
 - While encoding [RenderPassEncoder "Doom blit pass"].SetPipeline([Invalid RenderPipeline "Doom blit pipeline"]).

A scope keeps the first error and swallows the rest of what it captured: the pipeline layout, pipeline and bind group cascade is gone. The per-frame errors outside the scope still reach the uncaptured callback. A breakpoint in the pop callback, or a check right after the wait, lands next to the faulty creation code instead of at the next present.

Solution §6: error scope helper
static void OnPopErrorScope(WGPUPopErrorScopeStatus status, WGPUErrorType type, WGPUStringView message,
                            void* userdata1, void* userdata2)
{
    (void)userdata2;
    if (status == WGPUPopErrorScopeStatus_Success && type != WGPUErrorType_NoError)
        fprintf(stderr, "[scope %s] %.*s\n", (const char*)userdata1, (int)message.length, message.data);
}

// Blocks until everything since the push is validated. Debugging only.
static void PopErrorScope(const char* what)
{
    WGPUPopErrorScopeCallbackInfo info = WGPU_POP_ERROR_SCOPE_CALLBACK_INFO_INIT;
    info.mode                          = WGPUCallbackMode_WaitAnyOnly;
    info.callback                      = OnPopErrorScope;
    info.userdata1                     = (void*)what;

    WGPUFutureWaitInfo wait = WGPU_FUTURE_WAIT_INFO_INIT;
    wait.future             = wgpuDevicePopErrorScope(s_gpu.device, info);
    wgpuInstanceWaitAny(s_gpu.instance, 1, &wait, UINT64_MAX);
}

// DG_Init
wgpuDevicePushErrorScope(s_gpu.device, WGPUErrorFilter_Validation);
CreateFrameResources();
PopErrorScope("CreateFrameResources");

RenderDoc: where did writeTexture go?

Capture a frame with -vulkan. Things to find:

  • The copy Dawn records for wgpuQueueWriteTexture: a buffer-to-image copy from Dawn's staging memory, with its barriers, ahead of your render pass.
  • The descriptor set Dawn built from your bind group: one sampled image, one sampler, at the bindings you chose.
  • The frame texture in the texture viewer, labelled Doom frame. Alpha is 0, so the viewer may show it transparent until you disable the alpha channel.
  • The viewport: your letterbox rect, with Dawn's Y flip.
